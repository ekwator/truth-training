# Implementation Plan: Documentation Refactor v1.0.0

**Branch**: `001-docs-refactor` | **Date**: 2025-12-01 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `[specs/001-docs-refactor/spec.md](specs/001-docs-refactor/spec.md)`

## Summary

Refactor all Truth Training Markdown documentation for version v1.0.0 to achieve complete hyperlink integrity, zero orphaned files, and a clean separation between human-oriented docs under `/docs` and AI-oriented compressed specs under `/spec`.  
The implementation will use existing Spec-Kit doc-refactor tooling and lightweight Python-based analysis to build a full inventory, repair links, restructure content hierarchies, and generate machine-readable reports that Cursor agents can operate autonomously.

## Technical Context

**Language/Version**: Python 3.11 (documentation refactor tooling), Rust stable (core project), Node.js 20+ (desktop tooling), Bash (automation scripts)  
**Primary Dependencies**: Spec-Kit (`.specify`), `scripts/doc_refactor` Python package, Git, Markdown parsers, existing GitHub Actions/CI jobs  
**Storage**: File system (Markdown files, JSON/Markdown reports); no new database storage introduced  
**Testing**: Python unit tests and doc-refactor test suite, link-checking command runs, CI workflows invoking doc-refactor make targets, manual spot-checks of key navigation paths  
**Target Platform**: Linux primary (CI + development), with instructions and tooling kept OS-agnostic for macOS/Windows users  
**Project Type**: Multi-project mono-repo (Rust core/server/CLI, desktop, Android, docs, specs) with this feature scoped strictly to documentation artifacts  
**Performance Goals**: Full repository scan and link validation completes in under 5 minutes on a typical CI runner; incremental runs scale with number of changed `.md` files  
**Constraints**: Must not change the semantic content of `[CONTRIBUTING.md](CONTRIBUTING.md)`, `LICENSE.txt`, `[SECURITY.md](SECURITY.md)`, or `[CHANGELOG.md](CHANGELOG.md)`; all documentation must be accurate for v1.0.0 and respect cross-platform rules from the constitution  
**Scale/Scope**: All `.md` files in the repo (docs, specs, prompts, root files), including generated-but-committed Spec-Kit outputs
