# Documentation Refactor — Link Integrity

This guide explains how to normalize Markdown references, validate internal/external links, and interpret the reports generated by the link discovery pipeline.

## 1. Running Link Discovery

```bash
python scripts/doc_refactor/main.py run --phases link_discovery,validation
```

or use the Make target:

```bash
make doc-refactor-run
```

During `link_discovery` the CLI:

1. Normalizes bare `.md` paths (e.g., `docs/Guide.md`) into `[docs/Guide.md](docs/Guide.md)`.
2. Builds a reference graph rooted at every documentation node.
3. Validates each internal `.md` target against the inventory and marks status `ok` or `missing`.
4. Performs best-effort `HEAD` requests for external URLs and records `external_ok` or `external_warning`.

`validation` summarizes any outstanding issues and highlights orphan nodes that still need index coverage.

## 2. Reports

| File | Purpose |
|------|---------|
| `reports/doc_refactor/link_report.json` | Full node+edge graph. Includes `normalizations`, `plain_paths`, and per-edge `status`. |
| `reports/doc_refactor/validation.json` | Aggregated `missing_internal` and `external_warnings` with affected files. |

## 3. ReferenceEdge Status

Each edge in `link_report.json` looks like:

```json
{
  "source_path": "README.md",
  "target": "docs/Deployment.md",
  "link_text": "Deployment",
  "status": "ok",
  "is_external": false,
  "normalized": false
}
```

- `ok`: target resolved to a known documentation node.
- `missing`: internal `.md` path not found in the inventory — must be created or corrected before merging.
- `external_ok`: HTTP target responded with 2xx/3xx.
- `external_warning`: HTTP target failed or timed out. Investigate, but warnings do not automatically fail the pipeline.

## 4. Fixing Issues

1. **Missing internal links** — check for typos, renamed files, or index updates. After fixing, re-run `link_discovery`.
2. **External warnings** — verify the URL manually. If the site is down, update the target or annotate the doc with remediation notes.
3. **Plain paths** — any remaining entries in `validation.json["plain_paths"]` indicate code blocks or unusual formatting. Wrap these references manually.

## 5. Exit Criteria

- `validation.json["missing_internal"]` is empty.
- `validation.json["plain_paths"]` is empty.
- Any `external_warning` entries either link to reachable targets or are documented in the PR summary.

Link integrity gates are part of the overall release criteria (`[docs/Constitution-Compliance.md](docs/Constitution-Compliance.md)` and `[spec/14-quality-gates.md](spec/14-quality-gates.md)` now reference this workflow). Keep this document linked from the root `[README.md](README.md)` and triage failures before shipping v1.0.0 documentation updates.
